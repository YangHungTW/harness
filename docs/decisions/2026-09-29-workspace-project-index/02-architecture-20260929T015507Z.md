# Architecture -- workspace-project-index
Generated: 2026-09-29T01:55:07Z

The script contracts below are what `tests/workspace/run.sh`, the hook, and the skill all depend on. That shared dependency is why orchestration resolved to `single`.

## `scripts/workspace/discover.sh [ROOT]`
- `ROOT` defaults to `${CLAUDE_PROJECT_DIR:-$PWD}`.
- Output is one line per project, `<reldir>\t<git|dir>`, sorted with `LC_ALL=C`.
- **Project marker:** `.git` (dir or file), `.claude/`, `CLAUDE.md`, or `AGENTS.md`.
- **Scan:** depth 1 first. A depth-1 dir without a marker is descended once, to depth 2. Scanning stops at the first marker.
- **Skipped:** names starting with `.`, plus `node_modules`, `vendor`, `.venv`, `venv`, and `__pycache__`.
- Read-only. It never calls git.

## `scripts/workspace/propose.sh [ROOT]`
It prints `{"version":1,"projects":[...],"ignored":[...]}` to stdout and writes nothing.

| Field | Rule |
|---|---|
| `name` | slug of the basename; the full-reldir slug when basenames collide |
| `match` | unique of: the basename, the manifest name (`package.json` `.name` / pyproject `name =`), and the README-then-CLAUDE.md H1 split into tokens. Each token is 1-24 chars. Filenames like `CLAUDE.md` / `README` are dropped. At most 12 entries |
| `risk` | rule table:<br>• `live-money`: shioaji, ccxt, ib_insync/ib-insync, alpaca, fubon, or yuanta in package.json, pyproject.toml, or requirements*.txt<br>• `pii`: student, guardian, patient, national_id, or 身分證 in `*schema*` files at maxdepth 4, outside node_modules<br>• `prod-deploy`: vercel.json, fly.toml, netlify.toml, render.yaml, Procfile, or a `.github/workflows/*deploy*` file |
| `forbidDirectCommit` | `risk` is non-empty |
| `localFiles` | root `.env` / `.env.*` excluding example, sample, and template, each `sensitive: true, optional: false` |

- `note` and `redirectTo` are `null`.
- **`ignored`:** a `dir`-kind project with no manifest and no source file (`*.py`, `*.ts`, `*.tsx`, `*.js`, `*.rb`, `*.go`, `*.rs`, `*.php`, `*.swift`, `*.kt`) at maxdepth 3.
- It never reads prose beyond H1 lines.

## `scripts/workspace/validate.sh [FILE]`
- `FILE` defaults to `${CLAUDE_PROJECT_DIR:-$PWD}/.claude/workspace.json`.

| Exit | Meaning |
|---|---|
| 3 | missing file |
| 1 | invalid, with each `workspace.json: <reason>` on stderr |
| 0 | valid, with the JSON on stdout |

It enforces:
- **Top level:** keys ⊆ {version, projects, ignored}; version is 1.
- **Project keys:** ⊆ {name, dir, match, note, redirectTo, risk, forbidDirectCommit, localFiles}.
- **`name`:** matches `^[a-z0-9][a-z0-9-]*$` and is unique.
- **`dir`:** non-empty, relative, no `..` segment.
- **`match`:** 1-12 strings of 1-24 chars.
- **`risk`:** ⊆ {live-money, pii, prod-deploy}.
- **`redirectTo`:** null, or an existing name other than self.
- **`note`:** null, or ≤200 chars.
- **`localFiles[].path`:** relative, no `..`.

## `hooks/workspace-check.sh` (SessionStart, timeout 5)
Silent (exit 0, no output) when any of these hold:
- the opt-out is set
- `jq` is missing
- inside a git work tree
- discover finds fewer than 2 projects

Otherwise it prints `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":...}}` with one of two messages:
- **No config:** `yang-toolkit workspace: N projects, not configured -- run /yang-toolkit:workspace-init`
- **Config present:** unregistered = discovered − `projects[].dir` − `ignored[]`, giving `yang-toolkit workspace: N projects, K unregistered: a, b` with up to 5 names. When K is 0 the message says `all registered`.

It never writes. Scripts are located via `$(dirname "$0")/../scripts/workspace`.

## Prompt surfaces

- **`skills/workspace-init/SKILL.md`:**

  4. one review table and one confirmation
  5. Write the config
  6. validate
  7. sync the managed block
  8. `Complete when:`
